# Start Here

A path for absolute beginners. If you've written a few small programs (a loop, an `if` statement, a function) you have enough to begin. Go in order; each step builds on the one before.

## Step 1: Learn how to read a problem

A coding problem is a short story with rules hidden in it. Before writing any code, you pull out the inputs, the outputs and the limits.

- [[Reading a Problem]]

## Step 2: Learn how to measure a solution

Interviewers care about how fast your code is and how much memory it uses as the input grows. That's what "Big O" describes.

- [[Big O Notation]]
- [[Complexity]]

## Step 3: Pick a language roadmap

Use one language for every interview problem and get comfortable in it. Python is the friendliest place to start.

- [[Python Roadmap]]
- [[Python Comprehensions]] (a piece of Python syntax you'll see in every solution)
- [[CSharp Roadmap]] (if a job uses C# or .NET)

## Step 4: Learn the patterns, then do the problems

Most entry-level problems are one of a handful of patterns. Read a pattern note, then solve the problems that use it. Every problem note has a trace table: a step-by-step chart of what each variable holds on each pass through the loop. Fill it in by hand before you look at the solution.

Patterns, in a good learning order:

1. [[Arrays and Indexing]]
2. [[Hashing]]
3. [[Two Pointers]]
4. [[Simulation and Math]]
5. [[Stack]]
6. [[Sliding Window]]
7. [[Sorting]]
8. [[Binary Search]]
9. [[Linked Lists]]
10. [[Trees]]
11. [[Dynamic Programming]]

Each pattern note links its worked problems in the `03 Problems` folder (Python and C#).
